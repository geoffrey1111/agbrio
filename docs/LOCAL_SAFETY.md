# 运行保护

在电脑设置的「运行保护」中管理。远程手机与 MCP 不能替你修改这些本机设置。

## 资源告警

1. 在「监测磁盘与预警线」中查看本机固定磁盘和可用内存。
2. 勾选要监测的盘，分别拖动“剩余空间低于多少百分比”的滑块；内存也可设置剩余百分比。界面同时显示容量参考值。
3. 点击「保存并应用监测」，按需确认 Windows 管理员提示。旧规则在保存前继续生效；取消确认不应用设置。结果待确认时先刷新核对，不重复保存。
4. 选择接收资源告警的管理对话。可添加多个，按顺序排列：优先发给第一个，明确无法处理时转下一备用；送达不确定时先核对，不自动转发或重发。

只使用明确勾选的本机固定盘；已有配置中新发现的盘默认不勾选。采集为分时检查，不能保证阻止所有瞬间资源耗尽。通知只提供指标，不会清理文件、结束程序、重启应用或授权管理助手执行这些操作。

保存只重配当前用户、带有准确标记的资源采集器与普通权限单次捕获任务；不添加开机自启。正常使用不会持续创建额外采样进程。保存失败恢复原配置，无法确认的操作需刷新对账。告警接收方默认不绑定，由用户选择；Claude 接收方需要加载 Agbrio 插件并保持会话在线。

## Codex 模型故障恢复

所有监听的 Codex 对话默认启用，可在这里关闭。仅在明确的模型容量或临时服务故障、失败回合及同一原生 Goal 都核对一致时恢复已有目标。至少间隔60秒，每条对话30分钟内最多2次。

不自动更换模型、改变预算或权限，不恢复手动暂停或额度耗尽的目标，不创建新任务。未知发送结果先核对，不重复提交。达到上限或无法确认原因时交还用户处理。


资源告警从实际采样起只有2分钟有效。断线恢复、重新选择接收方或备用转发都不延长期限，过期不会补发。已提交但结果不明的原消息只核对回执，不自动重发；Claude会话已知忙碌时不领取新告警，并在原生提交门再次核对自身资源提示的期限。普通用户消息、Codex任务结果/提问通知不受这个资源期限限制。

告警正文显示带本机时区偏移的时间，避免把UTC误看成本地凌晨。数据库仍保留UTC采样身份；旧记录和已经发出的消息不被改写。Claude需加载插件0.1.17；`/reload-plugins`只负责重载已安装组件，不能代替更新插件。可在Claude插件管理中更新，或使用官方CLI `claude plugin update agbrio-bridge@agbrio-observation --scope user`，再于原会话空闲时重载。
