# 常见问题与排错

[从零开始的完整流程](SETUP.zh-CN.md) · [English FAQ](FAQ.md) · [返回首页](../README.zh-CN.md)

## 安装与版本

### 1. 第一次应该下载哪个版本？

统一使用 [最新推荐版本](https://github.com/geoffrey1111/agbrio/releases/latest)，0.1.34 只作历史版本。latest 推荐不等于全部场景都已验收。不要从聊天附件、第三方重打包或含私人数据的工作目录安装。

### 2. 我用 0.1.34 一直连接不了，怎么办？

先分清是本机 Codex 连接、手机配对还是 AI 助手 MCP。升级不能替你解决所有网络/账号问题。保存原始错误，再按 [升级与连接流程](SETUP.zh-CN.md) 更新指定包；不能只凭版本就保证修复，不需要反复重装或清数据。

### 3. 要买兑换码吗？要重新买 Codex 吗？

自部署不要求兑换码。托管入口是可选服务，按实际可用性单独提供。使用自己的 Codex/Claude 账号和额度；Agbrio 不赠送、重置或绕过原平台额度。连接配置不需要发送付费测试消息。

### 4. SHA256、更新签名与 Windows 安全提示是一回事吗？

不是。SHA256 对照公开文件身份，`.sig` 用于可信更新 key 的验证；它们不是 Windows Authenticode 签名。不要为了消除提示关闭安全策略。先核对官方发行页及文件身份，再由本人决定是否继续。

## Codex 连接

### 5. 必须用特别的方式打开 Codex 吗？

不用。按平时的方式打开，Agbrio 会自动连接；不再有共享入口、退出重开或常驻后台。[连接原理](CODEX_LIGHT_CONNECTION.md)。

### 6. 这种连接做不到什么？

不能从 Agbrio 修改 Goal，不支持以管理员身份启动 Codex，退出 Codex Desktop 后任务不会继续，也没有逐字流式显示。它不会减少 Codex 自身占用的内存。

发给没在 Codex 打开的对话的任务，跑在 Agbrio 的临时后端上。结束前 Codex 会提示“已在另一个应用中打开”，退出 Agbrio 会中断它；结束几秒后在 Codex 点“重试”即可打开。通过 Agbrio 新建的对话，可能要重新打开 Codex 才会显示。

### 7. 设置里提示旧的共享后台还在，怎么办？

在弹窗中确认，或到“设置 → Codex”使用同样的操作。正在运行的任务会中断且不会重发，正在使用它的 Codex 窗口要重新打开。不想中断任务的话，等任务结束并退出 Codex，Agbrio 会自动关闭它。如果显示错误码，说明没有结束任何进程；重新打开 Agbrio 会再试，持续失败请反馈这个错误码。不要结束所有 Node。[升级说明](SETUP.zh-CN.md)。

### 8. Codex 提示对话已在另一个应用中打开，怎么办？

手机或助手发出的任务正在临时后台上运行这个对话。任务结束几秒后 Desktop 就能打开。想实时看任务，先在 Desktop 打开这个对话再发送。

### 9. ChatGPT Bridge 和 Router 浏览器去哪了？

已移除。带 ChatGPT 端的 Bridge 保留已保存的回复，要继续使用请把那一端重新绑定到 Codex 或 Claude Code。通过 MCP 把 ChatGPT 接成 AI 助手仍然可用。

### 9a. 为什么任务管理器里会有多个 Node？

应用、插件和工具可能各有自己的子进程；数量多本身不能判断泄漏，也不能判定都属于 Agbrio。异常持续增长或退出后残留要按父进程、启动时间和实例身份查，不能“结束所有 Node”当作常规使用步骤。

## Bridge、消息和目标

### 15. 选了同名对话，怎么保证发对？删除 Bridge 会删原对话吗？

路由用原生稳定 ID，标题只用于展示。绑定时核对项目/身份和方向；删除本地 Bridge 不删除原生对话。已删除 Bridge 仍显示占用属于应反馈的问题，不应通过删数据库或抢走另一个有效绑定解决。

### 16. 发一次消息为什么没有目标完成回复？可以再点吗？

发送、原生接受、目标执行和目标完成是不同阶段。`SENT` 不等于目标任务完成；`UNKNOWN` 也不等于没发。先看原请求回执及精确目标历史，不要因网络慢或通知重复而创建另一次发送。

### 17. 能只转发一部分内容吗？文件是不是自动上传？

可以选段并编辑，最后核对正文、接收端和文件。Codex 文件交接是复制到目标项目 `.aiwr/incoming/<handoff-id>/` 并附路径/哈希，不等于自动作为图片输入。

### 18. 红点没了、“AI 助手已处理”或显示旧结果代表什么？

这些是阅读和过渡提示，不是发送凭证。目标执行中可能仍保留上一段完整结果；以当前执行状态、完整回复身份及独立交接回执判断，不把旧结果重复当成新待办。

### 19. 目标暂停、回合失败、等待决策和任务完成有什么区别？

Goal 是持续目标，turn 是一次执行，待审批/问题又是另一层。先核对原目标和对话、授权、pending 决策和 UNKNOWN 发送。只在支持的原生状态暂停/继续，不重建目标、不自动加预算、不重发旧交接。[详细控制边界](GOAL_RECOVERY.md)。

## 手机、助手及 Claude

### 20. 为什么手机显示旧内容或加载很慢？

缓存可先展示，不证明电脑在线。检查 Host、电脑休眠、网络及 HTTPS 入口，再核对当前界面版本。界面更新入口在关于里。不要先清空站点数据、删 PWA 或重新配对，避免丢登录/草稿。手机界面更新不等于桌面 Host 更新。

### 21. 电脑关机后，手机或 dot 还能继续执行吗？

本机 Host/代理离线时不能实时读取或控制本机工作，缓存只能提供旧信息。手机安装 PWA 不会把 Windows 后端搬到手机。设备推送受系统和权限影响，收到推送也不是交接完成。

### 22. 手机配对成功，AI 助手是不是也接管了？

没有。设备配对、OAuth 授权、客户端发现工具和具体工作委托是不同步骤。按 [助手教程](ASSISTANT_CONNECTION_GUIDE.zh-CN.md) 在正确客户端验收，并明确 Bridge 范围/方向/暂停条件，不默认授权所有项目。

### 23. 配好普通 MCP 工具，Events 和日报就自动有了吗？

没有。Events 要平台支持、实际订阅并验证真实唤醒；历史测试不代表你的订阅已存在。日报要你明确提交时间/时区/目的地/范围，并由真实定时工具保存验证；不支持则未启用。重复连接应复用/更新既有任务。[Events](MCP_EVENTS_WORKFLOW.zh-CN.md) · [日报](DAILY_REPORTS.md)。

### 24. Events 已 HTTP 200，但助手没处理，算成功吗？

不算。要分别证明投递、真实唤醒、来源读取、去重、prepare/review/send 与独立 receipt。平台事件详情注入仍有已知缺口；仅在用户预先批准后可使用既有委托范围的扫描 fallback，不能擅自轮询或扩大范围。[真实通过范围和限制](MCP_EVENTS_WORKFLOW.zh-CN.md)。

### 25. Claude 插件安装了，为什么没有会话或不能回复？

配置保存、插件重载、真实会话注册、手动输入协议就绪不是一回事。等原任务完成再安全重载，不发额外诊断文字、不用 `--force`。手动回复需要插件 0.1.3 实际注册 protocol 1；只有观察接入不等于可发送。自主/MCP Claude 写入和 Claude Goal 管理仍不支持。[Claude 说明](CLAUDE_CODE.md)。

### 26. 提交问题最少需要什么？

Agbrio 与 Codex 版本、Windows 版本、是 Codex/手机/助手哪条连接、使用哪个入口、失败的那一步、原始错误文字和时间、是否有活动任务。不要公开私有对话、用户名路径、二维码、callback 完整 URL、cookie、token 或密钥。[提交问题](https://github.com/geoffrey1111/agbrio/issues/new?template=bug_report.yml)。
