# 常见问题与排错

[从零开始的完整流程](SETUP.zh-CN.md) · [English FAQ](FAQ.md) · [返回首页](../README.zh-CN.md)

## 安装与版本

### 1. 第一次应该下载哪个版本？

稳定下载仍是 0.1.34；需要后续共享连接修复时，查看 [0.1.35-rc.5 候选版](https://github.com/geoffrey1111/agbrio/releases/tag/v0.1.35-rc.5) 及其限制。GitHub 的 latest 不代表最新候选版。不要从聊天附件、第三方重打包或含私人数据的工作目录安装。

### 2. 我用 0.1.34 一直连接不了，怎么办？

先分清是本机共享 Codex、手机配对还是 AI 助手 MCP。rc.5 修复了共享启动状态保存、组件保留及回退入口；它不能替你解决所有网络/账号问题。保存原始错误，再按 [升级与连接流程](SETUP.zh-CN.md) 更新指定包；不能只凭版本就保证修复，不需要反复重装或清数据。

### 3. 要买兑换码吗？要重新买 Codex 吗？

自部署不要求兑换码。托管入口是可选服务，按实际可用性单独提供。使用自己的 Codex/Claude 账号和额度；Agbrio 不赠送、重置或绕过原平台额度。连接配置不需要发送付费测试消息。

### 4. SHA256、更新签名与 Windows 安全提示是一回事吗？

不是。SHA256 对照公开文件身份，`.sig` 用于可信更新 key 的验证；它们不是 Windows Authenticode 签名。不要为了消除提示关闭安全策略。先核对官方发行页及文件身份，再由本人决定是否继续。

## 共享 Codex

### 5. 为什么教程以前让我先打开普通 Codex，再退出？

早期准备依赖正在运行的官方后端。准备与切换又是两步，不能直接把一个工作中的普通窗口换成共享后端。**rc.5 能在 Desktop 关闭时发现官方安装，不再要求每次先开普通版。** 新用户只需先完成官方安装和登录，随后按共享入口使用。

### 6. 以后每次都得打开 Bridge，再开 Codex 吗？

rc.5 的 **Codex (Agbrio shared)** 开始菜单入口可以独立启动，不要求先开 Agbrio 窗口。使用 Bridge、手机和助手读取时仍需运行 Agbrio Host。共享入口和 Host 是相关的两个部分，不是同一个窗口。

### 7. 我的官方快捷方式、任务栏图标会自动变成共享模式吗？

不会。官方入口保留原行为；需要共享时使用或固定 **Codex (Agbrio shared)**。已经从普通入口打开时，先结束任务并正常退出，再切换，不能同时开两个后端抢同一份工作。

### 8. “共享连接已准备好”是不是成功了？

只表示后台准备完成。还要 **打开共享 Codex**，并看到 **Desktop 已接入共享连接**。手机配对和助手授权另外验证；其中一个成功不能代替另一个。

### 9. 提示普通 Codex 仍在运行、对话正在执行怎么办？

这是切换保护。保存工作，等任务结束，再正常退出整个 Desktop；仅关闭一个窗口可能没有退出后台。不要反复点击，不要强制关闭活动任务，不要批量杀 Node。如果已经退出仍报错，记录时间和错误码供精确身份诊断。

### 10. 重启电脑或 Codex 官方更新后需要重配吗？

同一用户重启后使用共享入口，通常不需重建 Bridge、重登账号或重配手机。共享入口在空闲启动时检查官方安装和组件。官方更新仍走官方渠道；接口改变可能使验证失败，**不承诺所有未来版本无缝兼容**，也不会热换正在执行的任务。保留版本/错误后回普通入口，等待兼容修复。

### 11. 工具宿主缺失、校验失败、共享入口没有窗口怎么办？

先保存完整 `SHARED_...` 错误码及失败阶段，核对是否确实安装了 rc.5 和完整官方 Codex。不要从网上随便找一个 `codex-code-mode-host.exe` 填进去，不复制他人安装/登录目录，不反复重启。参照 [回退步骤](SETUP.zh-CN.md) 恢复普通使用，再提交脱敏诊断。旧的泛化“未打开”提示不能唯一定位根因。

### 12. 怎么停掉共享？会不会关掉别的 Node？

保存工作、正常退出共享 Desktop，然后用 **Codex (return to normal)** 或 Agbrio **停用共享连接**。只有确认停用后才从官方入口打开。工具按本次实例、进程创建身份和血缘处理，不按进程名称全杀。后台无响应时的明确恢复确认可能中断共享工作；身份不明则保留并报告，不承诺强行清理任意进程。

### 13. 为什么任务管理器里会有多个 Node？

应用、插件和工具可能各有自己的子进程；数量多本身不能判断泄漏，也不能判定都属于 Agbrio。异常持续增长或退出后残留要按父进程、启动时间和实例身份查，不能“结束所有 Node”当作常规使用步骤。

### 14. 共享连接就是一个 MCP 吗？不用共享行不行？

不是。共享模式让官方 Desktop 与 Agbrio 对同一个后端操作；MCP 是给外部助手的受控工具接口，不能单靠配置 MCP 接管已经打开的普通 Desktop 后端。Agbrio 不要求你永久改变官方启动；但需要 Desktop 和 Router 继续同一段实时 Codex 工作时，应验证共享连接，普通模式不能被假定具有相同的协同能力。

## Bridge、消息和目标

### 15. 选了同名对话，怎么保证发对？删除 Bridge 会删原对话吗？

路由用原生稳定 ID，标题只用于展示。绑定时核对项目/身份和方向；删除本地 Bridge 不删除原生对话。已删除 Bridge 仍显示占用属于应反馈的问题，不应通过删数据库或抢走另一个有效绑定解决。

### 16. 发一次消息为什么没有目标完成回复？可以再点吗？

发送、原生接受、目标执行和目标完成是不同阶段。`SENT` 不等于目标任务完成；`UNKNOWN` 也不等于没发。先看原请求回执及精确目标历史，不要因网络慢或通知重复而创建另一次发送。

### 17. 能只转发一部分内容吗？文件是不是自动上传？

可以选段并编辑，最后核对正文、接收端和文件。Codex 文件交接是复制到目标项目 `.aiwr/incoming/<handoff-id>/` 并附路径/哈希，不等于上传成 ChatGPT 附件或自动作为图片输入。

### 18. 红点没了、“AI 助手已处理”或显示旧结果代表什么？

这些是阅读和过渡提示，不是发送凭证。目标执行中可能仍保留上一段完整结果；以当前执行状态、完整回复身份及独立交接回执判断，不把旧结果重复当成新待办。

### 19. 目标暂停、回合失败、等待决策和任务完成有什么区别？

Goal 是持续目标，turn 是一次执行，待审批/问题又是另一层。先核对原目标和对话、授权、pending 决策和 UNKNOWN 发送。只在支持的原生状态暂停/继续，不重建目标、不自动加预算、不重发旧交接。[详细控制边界](GOAL_RECOVERY.md)。

## 手机、助手及 Claude

### 20. 为什么手机显示旧内容或加载很慢？

缓存可先展示，不证明电脑在线。检查 Host、电脑休眠、网络及 HTTPS 入口，再核对当前界面版本。界面更新入口在关于里；rc.5 设置首页也有一个。不要先清空站点数据、删 PWA 或重新配对，避免丢登录/草稿。手机界面更新不等于桌面 Host 更新。

### 21. 电脑关机后，手机或 dot 还能继续执行吗？

本机 Host/代理离线时不能实时读取或控制本机工作，缓存只能提供旧信息。手机安装 PWA 不会把 Windows 后端搬到手机。设备推送受系统和权限影响，收到推送也不是交接完成。

### 22. 手机配对成功，AI 助手是不是也接管了？

没有。设备配对、OAuth 授权、客户端发现工具和具体工作委托是不同步骤。按 [助手教程](ASSISTANT_CONNECTION_GUIDE.zh-CN.md) 在正确客户端验收，并明确 Bridge 范围/方向/暂停条件，不默认授权所有项目。

### 23. 配好普通 MCP 工具，Events 和日报就自动有了吗？

没有。Events 要平台支持、实际订阅并验证真实唤醒；历史测试不代表你的订阅已存在。日报要你明确提交时间/时区/目的地/范围，并由真实定时工具保存验证；不支持则未启用。重复连接应复用/更新既有任务。[Events](MCP_EVENTS_WORKFLOW.zh-CN.md) · [日报](DAILY_REPORTS.md)。

### 24. Events 已 HTTP 200，但助手没处理，算成功吗？

不算。要分别证明投递、真实唤醒、来源读取、去重、prepare/review/send 与独立 receipt。平台事件详情注入仍有已知缺口；仅在用户预先批准后可使用既有委托范围的扫描 fallback，不能擅自轮询或扩大范围。[真实通过范围和限制](MCP_EVENTS_WORKFLOW.zh-CN.md)。

### 25. Claude 插件安装了，为什么没有会话或不能回复？

配置保存、插件重载、真实会话注册、手动输入协议就绪不是一回事。等原任务完成再安全重载，不发额外诊断文字、不用 `--force`。手动回复需要插件 0.1.3 实际注册 protocol 1；只有观察接入不等于可发送。自主/MCP Claude 写入和 Claude Goal 管理仍不支持。[Claude 说明](CLAUDE_CODE.md)。

### 26. ChatGPT 出现验证码/安全提示，能自动刷新解决吗？

不能。停止自动导航、刷新和提交，由本人完成账号安全步骤。不要复制日常浏览器 cookies、换账号/指纹或循环重试。实验性浏览器适配不等于所有 ChatGPT 会话已验证稳定。

### 27. 提交问题最少需要什么？

Agbrio 与 Codex 版本、Windows 版本、是共享/手机/助手哪条连接、使用哪个入口、失败的那一步、原始错误文字和时间、是否有活动任务。不要公开私有对话、用户名路径、二维码、callback 完整 URL、cookie、token 或密钥。[提交问题](https://github.com/geoffrey1111/agbrio/issues/new?template=bug_report.yml)。
