# Agbrio 完整使用流程（Windows + Codex + 手机）

适用范围：2026-10-22 公开版本。请先看版本，再按步骤操作；手机、Claude Code、AI 助手都是可选项，不必一次全部配置。

[常见问题与排错](FAQ.zh-CN.md) · [English](SETUP.md) · [返回首页](../README.zh-CN.md)

## 下载当前最新版

统一下载 [0.1.35-rc.53 共享连接修复版](https://github.com/geoffrey1111/agbrio/releases/latest)。它现为最新推荐版本，0.1.34 只保留历史下载；已有 0.1.34 用户按下文升级，不必在两个推荐版本之间选择。

当前 main 源码构建的包内版本号为 **0.1.35-rc.53**。设为 latest 不会改变安装器/签名，也不代表所有未来 Codex 更新、历史对话和崩溃场景都已验收。[准确包身份与验证限制](RELEASE_0.1.35-rc.53.md)。安装包提供通用看板入口，不含私人看板内容、原画或运行数据。

## 1. 先理解三个东西

- **Codex Desktop**：你原来使用的官方桌面应用及账号。
- **Agbrio 桌面 Host**：本机连接、Bridge、交接记录和手机入口的后台。关闭窗口通常仍留在托盘；退出托盘应用才停止 Host。
- **共享 Codex 入口**：让同一个官方 Desktop 与 Agbrio 使用共享后端。它不是第二个 Codex 账号，也不是普通 MCP 插件。

**准备好连接 ≠ Desktop 已接入 ≠ 手机已配对 ≠ AI 助手已授权。** 四步分别验证，不要看到其中一个成功就假定全部可用。

## 2. 安装或从 0.1.34 更新

想交给自己的 Codex 操作？[复制完整升级指令](UPGRADE_WITH_AI.zh-CN.md)，仍需本人完成必要退出及账号/系统确认。

1. 准备 Windows x64、自己的官方 Windows Store Codex Desktop、有效登录和网络。若从未使用过 Codex，先通过官方入口完成安装与登录；不必为 Agbrio 新建账号。
2. 从选定的发行页下载 `x64-setup.exe`，对照同页 `SHA256SUMS.txt`。例如在 PowerShell 中运行 `Get-FileHash -Algorithm SHA256 -LiteralPath '安装器的完整路径'`；不匹配不要安装。
3. 保存工作。升级前从托盘正常退出 Agbrio，避免两个实例同时运行。需要切换共享模式时，等 Codex 当前任务完成，再正常退出 Codex；不要强制杀正在运行的任务。
4. 运行安装器并保留既有数据，不删除配置、登录、Bridge、草稿或配对信息。若需要 Windows 确认，由你本人核对来源后决定。
5. 打开 Agbrio，在设置/关于核对版本。rc.53 安装后在开始菜单应有 `Codex (Agbrio shared)` 与 `Codex (return to normal)`。

发行页的 `.sig` 是应用更新校验签名，**不代表安装器具备 Windows Authenticode 签名或一定没有 SmartScreen 提示**。校验值相同也不等于所有功能已完成真人验收。

## 3. 为什么以前要“普通 Codex → 连接 → 退出 → 共享”？

旧教程让普通 Codex 先运行，是为了识别正在使用的本机后端；准备连接和真正切换连接是两步。正在运行的普通 Desktop 已持有自己的后端，Agbrio 不能安全地把它直接换成另一个写入方，所以第一次切换要先结束当前任务、退出普通 Desktop，再从共享入口打开。

**rc.53 已能在 Desktop 关闭时从已注册的官方安装中发现并校验完整本机组件。安装和账号准备完成后，不需要每次先开普通版再关掉。** 它仍会拒绝在普通 Desktop 正运行时另起一套共享 Desktop，也不会替你强制退出工作。

这里的共享连接是兼容集成，**不是 OpenAI 官方承诺的远程接管功能**；接口或安装布局变化时可能拒绝启动。不要把“能配置 MCP 工具”和“Agbrio 与 Desktop 共用同一后端”当成同一件事。

## 4. 第一次真正连接（rc.53）

任选一种入口，按同一顺序验证：

### 方式 A：从开始菜单直接启动

1. 确认官方 Codex 已安装、登录准备完成。
2. 当前若有普通 Codex 工作，先保存、等任务完成，再使用应用的正常退出功能；只关一个窗口不一定代表后台已退出。不要结束所有 Node。
3. 打开开始菜单 → **Codex (Agbrio shared)**。入口会检查安装、工具组件和既有共享状态，再启动官方 Desktop；独立入口不要求先打开 Agbrio 窗口。
4. 要在 Agbrio 或手机中读写，仍需启动 Agbrio Host。进入设置 → Codex 查看实际连接状态。

### 方式 B：从 Agbrio 设置启动

1. 在普通 Codex 已正常退出时，进入 **设置 → Codex → 准备共享连接**。
2. 等待验证；**共享连接已准备好**只说明后台准备完成。
3. 点击 **打开共享 Codex**。
4. 等待 **Desktop 已接入共享连接**。这才说明 Desktop 与 Router 已共用后端。

若提示正在执行、需要退出、工具验证失败或身份不明，停止切换，按 [FAQ](FAQ.zh-CN.md) 对应条目处理，不连续点击或强制结束进程。

## 5. 以后每天怎么打开？重启、更新怎么办？

| 场景 | 操作 |
| --- | --- |
| 以后要使用共享模式 | 直接打开 **Codex (Agbrio shared)**；不需要先开普通版，也不必先打开 Agbrio 的窗口。需要 Bridge/手机时保持 Host 运行。 |
| 电脑重启后 | 登录同一个 Windows 用户，再用共享入口；不重新配对所有手机、不重新建 Bridge。开机自动运行不作保证。 |
| 点击原来的官方图标/任务栏图标 | 仍是官方默认启动，**没有自动改绑为共享模式**。把共享入口固定到自己的快捷位置，并辨认两个入口。 |
| 普通模式已经打开 | 完成当前任务、正常退出，再开共享入口；不能在普通窗口工作中强切。 |
| Codex 官方更新 | 继续由官方渠道更新。空闲启动时共享入口会重新发现和校验组件；正在执行时不热换后端。不能保证未来所有版本兼容。 |
| 显示共享后端待更新 | 完成任务、退出共享 Desktop、正常停用共享连接，再准备/打开；失败保留错误，不循环重配。 |
| 想完全回到普通 Codex | 按下文回退，再使用原官方入口。 |

不必为了连接而重新登录、复制账号目录、修改证书或关闭安全检查。安装目录改变、官方包无法识别等情况必须先查错误，不能猜路径强行通过。

## 6. 建立第一个 Bridge

1. 先在原生应用准备两段你确实要协作的对话，例如“项目管理”与“实现任务”。使用真实已有对话即可，设置连接不需要发送付费测试消息。
2. 在 Agbrio 的 **Bridge** 页面新建，填写便于识别的名称。
3. 分别选择控制端和执行端；核对标题、项目目录以及可查看的身份信息。实际路由按原生稳定 ID，重名对话不能只看标题。
4. 保存，打开两端查看来源、当前状态和回复。不要把缓存正文当成已经在线的证明。
5. 更换两端时重新核对；一条仍被有效 Bridge 占用的对话不能静默抢走。删除 Bridge 只删除本地关联，不删除原生对话。

## 7. 完成一次人工交接

1. 打开来源端，等完整回复就绪；正在执行的状态不等于产生了新的完整结果。
2. 选择需要交接的指令/结果段落及必要文件；分析无需全部转发。
3. 进入编辑和预览，核对**完整最终正文、接收端、方向与附件**。
4. 确认发送一次，查看原记录的进度和回执，不需要“知道了”二次确认。
5. `SENT` 表示该次交接已确认送达，**不表示目标任务已完成**。继续查看目标执行状态及下一次完整回复。
6. 若出现 `UNKNOWN`、超时或不确定，先检查同一请求的回执和精确目标历史。不要因没看到回复就点多次发送、换请求 ID 重试。

Codex 本地文件交接会在目标项目 `.aiwr/incoming/<handoff-id>/` 放置文件，正文含相对路径和 SHA-256；这不是 ChatGPT 附件上传，也不意味着图片已自动成为所有模型的图像输入。发送前检查预览中的实际支持范围。

## 8. 监听、通知、提问与目标

- **监听**适合单独关注一段对话，无需为了通知建立两端 Bridge。暂停监听不删除原生对话；已暂停项排在活跃项后面，访问期间顺序保持稳定。
- **通知**是提醒；打开后核对原对话的最新状态。历史通知不代表仍需交接，也不代表已经送达下一端。
- **回答问题**：对支持的 Codex 问题卡选择或补充回答，检查它属于哪一端、哪一次请求。不支持的审批/原生操作回到相应原应用。
- **Goal 目标**显示原生目标及计时/状态，可对支持的目标暂停或继续。Goal、当前回合、审批和发送状态是不同维度；完成或预算耗尽不能当作普通暂停恢复。详见 [目标控制及限制](GOAL_RECOVERY.md)。
- **AI 助手已处理**提示用于交接后的过渡；核实独立回执才判断处理成功，不以红点或提示文字代替发送证据。

## 9. 在手机上使用（可选）

1. 保持电脑、Agbrio Host 和所需代理/共享连接在线，电脑不要休眠。手机不是独立运行任务的服务器。
2. 桌面 **设置 → 设备**选择入口：已有 HTTPS/Cloudflare/Tailscale 或可选托管兑换码。自部署不要求购买兑换码。
3. 自部署使用界面的 **复制部署指令**，让助手按真实端口配置；保存前须验证 HTTPS 到达你的这个实例。不要开放一个未鉴权的公网端口或发送凭据给他人。
4. 打开桌面提供的手机地址，生成配对码并输入；不要使用其他安装/他人的二维码。
5. iPhone 用 Safari“添加到主屏幕”；在设备和浏览器支持时允许通知，其他设备按其安装/通知能力操作。配对成功不等于推送权限已允许。
6. 手机与桌面读取同一个 Host。更换 HTTPS 域名属于新来源，需要在那里重新配对及注册通知。

公网、局域网、设备数量、续期、撤销、反向代理与 Tailscale/Cloudflare 部署细节见 [手机入口部署说明](PHONE_SETUP.md)。不方便暴露公网时可选择私有 tailnet，但手机也要连接相应网络。

## 10. 接入 AI 助手、Events 和日报（均可选）

1. 设置 → AI 助手，先选 **ChatGPT / dot 云端**或 **Codex 本地**。复制本实例的指令，确认要连接的真实客户端。
2. 由本人完成账号同意；不要公开 OAuth 凭据或完整私密配置。连接后在客户端重新发现工具，执行真实只读验收。Agbrio 显示准备好不等于远端已连上。
3. 明确告诉助手接管**哪些 Bridge、哪些方向、做什么、何时必须问你、如何暂停**。应用级访问不代表所有项目都委托。
4. 只有明确委托内的普通交接才由助手审阅后推进；范围变化、要求冲突或待决策时仍需询问。始终保留 prepare → review → send → receipt 与防重复。
5. **Events**需要平台本身支持事件发现/订阅，并由助手实际创建和验证订阅；普通 MCP 读取成功不代表订阅存在。真实唤醒但缺少事件详情时，仅在你预先批准的范围扫描 fallback 内处理，不能自动扫描新 Bridge。详见 [Events 完整流程](MCP_EVENTS_WORKFLOW.zh-CN.md)。
6. **日报**在只读验收后可选配置：建议本地 22:00，明确时区、发送位置和 Bridge 范围，复制并明确提交请求。助手必须检查真实定时工具、核对既有任务并验证保存；不支持就说明未启用，重复连接不能再建一份。详见 [日报统计及计窗规则](DAILY_REPORTS.md)。

[逐步连接助手](ASSISTANT_CONNECTION_GUIDE.zh-CN.md)。OAuth 不自动批准任意定时任务；过去的 Events 实验不代表新用户已建立订阅。

## 11. 使用 Claude 桌面应用里的 Code（可选）

1. Bridge 选择两端或监听选择对话时，切换 **Claude Code**；首次配置在桌面点 **连接 Claude Code**，手机只能选择已经接入的会话。
2. 复用已有插件配置和凭据。等待真实会话注册，核对标题、目录和原生 session 身份；“已配置”不等于“原会话已连接”。
3. 需要重载时，等原任务结束，在原会话使用内置 `/reload-plugins`，不要加 `--force`、不要发诊断文字/模型测试消息。遇到费用或强制加载提示先停下。
4. 收取的是适配器实际观察到的状态和回复，不保证补全接入前所有历史。
5. 只有实际加载插件 0.1.3 并注册 manual-input protocol 1 后，才可在已鉴权桌面/PWA **回复原对话**发送你本人需要的文字。独立原生存储回执才算 `SENT`；不确定不自动重发。
6. Claude 的自主/MCP/跨提供商写入、附件、Goal 管理、abort/steer 不在此授权能力内；不要用 Codex 的目标按钮推断 Claude 也支持。

[Claude 能力与限制](CLAUDE_CODE.md)。插件重载成功本身不证明真实发送已验收。

## 12. 更新、回退与反馈

- **更新 Agbrio**：设置中检查 Windows 更新；也可使用当前发行页。保留原数据，不用卸载清库。0.1.34 为历史版本，最新下载入口指向共享修复版。
- **更新手机界面**：手机关于中的界面更新入口。界面更新与 Windows Host 更新是两层，不因换壳自动升级后台。不要为更新清配对和草稿。
- **回普通 Codex**：保存工作，正常退出共享 Desktop，再运行 **Codex (return to normal)** 或 Agbrio 中 **停用共享连接**；确认停用后从官方入口打开。独立回退入口不依赖 Agbrio 窗口。
- **后台无响应**：回退工具只对能证明属于本次实例的进程提供明确确认，默认不确认；可能中断未完成工作。身份不明就停止并报告，不能保证清理任意残留，不要结束所有 Node。
- **反馈**：提供 Agbrio/Codex/Windows 版本、使用哪个入口、失败步骤、原始错误码与时间、是否仍有任务运行。先删除对话正文、用户名路径、完整 callback URL、token、二维码及密钥。使用 [问题模板](https://github.com/geoffrey1111/agbrio/issues/new?template=bug_report.yml)。

公开已验证项与剩余限制见 [版本说明](RELEASE_0.1.35-rc.53.md)；单次连接成功不代表全部历史、Code Mode、未来更新或所有崩溃恢复都通过。
